# Bilingual copy — English and Castellano

The site ships in two languages, switched from the EN / ES control in the
header. Everything a reader sees changes: copy, number separators, currency,
dates, ordinal suffixes, and the generated text from the models.

## The contract

`src/i18n/en.ts` is the source of truth — one big `as const` object, exported
with `export type EnglishDict = typeof en`.

`src/i18n/es.ts` is annotated `DictOf<EnglishDict>`. That mapped type
(`src/i18n/types.ts`) walks the English object and demands the same keys, with
the same interpolation-function signatures. So:

- a **missing** Spanish key is a compile error,
- a **misspelt** key is a compile error (excess property check),
- an interpolation function with the **wrong argument list** is a compile error.

"Fully bilingual" is enforced by `tsc`, not by hoping somebody remembered.
Adding a string is therefore a two-file edit by construction — `npm run build`
fails until the Spanish side exists.

Interpolation uses plain functions rather than `{{placeholders}}`:

```ts
sub: (shown: number, total: number, season: string) =>
  `${shown} of ${total} players · ${season} season`
```

The arguments stay type-checked, and each language puts the pieces in its own
order — which matters, because `${conf} Conference` has to become
`Conferencia ${conf}`, not `${conf} Conferencia`.

## Using it

```ts
const { t, f, locale, setLocale } = useI18n()
```

`t` **is** the dictionary, not a lookup function, so `t.player.tabs.career` is
resolved at compile time. `f` is the locale-aware formatter set that replaces
the old `@/lib/format` helpers:

| call | `en` | `es` |
|---|---|---|
| `f.dec(113.5)` | `113.5` | `113,5` |
| `f.int(20052)` | `20,052` | `20.052` |
| `f.money(55_200_000)` | `$55.2M` | `55,2 M$` |
| `f.pct(0.661, 1)` | `66.1%` | `66,1%` |
| `f.ordinal(3)` | `rd` | `º` |
| `f.shortDate(iso)` | `Mar 14` | `14 mar` |
| `f.monthLabel('2026-01')` | `Jan 26` | `ene 26` |

`money` passes `currencyDisplay: 'narrowSymbol'`; the Spanish default is `US$`,
which turns a compact figure into the unreadable `55,2 MUS$`.

`dec`, `signed` and `pct` leave grouping **off** by default, so a stat line
reads `1234.5` rather than `1,234.5`; pass `group: true` where a figure is big
enough to need separators (`CountUp` does this above 9,999).

The locale is persisted to `localStorage` and stamped on `<html lang>`. First
visit follows `navigator.language`, then the reader's choice wins.

## Text the models generate

Three places produce sentences from data rather than from the dictionary. None
of them may hold a language, so all three emit **tokens** and let the render
site write the sentence.

**Play-by-play.** The simulator runs in a Web Worker, which has no store and no
dictionary — and a result cached from an earlier run would freeze whatever
language it was generated in. So `SimEvent` carries a `play?: PlayDescriptor`
(`src/types/index.ts`) describing what happened:

```ts
| { t: 'made'; actor: string; kind: ShotKind; assist?: string; andOne: boolean }
| { t: 'blocked'; actor: string; kind: ShotKind; blocker: string }
```

`GameBroadcast` turns that into `t.sim.events.*`. Switching to Spanish
re-narrates a game you have already watched instead of leaving English in the
log. `event.text` remains as the English fallback and is what a copied
play-by-play contains.

**Loader stages.** The worker reports progress as a fixed English token
(`'Locking rosters'`); `stageLabel()` in `GameLoader`, `Builder` and `League`
maps it back to `t.sim.*` / `t.league.stage*` where the locale is known.

**Scouting reports.** `archetype()` returns an `ArchetypeKey` (`'primaryEngine'`)
rather than a label, and `scoutingReport()` returns `ReportNote[]` — a
discriminated union of thresholds that fired, with their numbers already
formatted through `fmt()`. `ScoutingPanel` switches on `note.k` and calls the
matching `t.scouting.report[k](...)`. The rule stays deterministic and
language-free; only the sentence around it changes.

The same pattern covers award components (`t.season.parts.*`), leader
categories (`t.stat[key]`), playoff round names (`t.league.rounds.*`) and
projection drivers (`t.predictPlayer.drivers.*`) — each mapped at the render
site, with the raw English label as the fallback if a key is ever missing.

## What deliberately stays in English

NBA jargon that Spanish broadcasts use untranslated: *rookie, playoffs,
play-in, MVP, box score, win shares, BPM, VORP, PER, TS%*. Team and player
names, team abbreviations, division names (proper nouns), and glyphs like
`+/-`. Conference names **are** translated (`East` → `Este`), because they
read as words rather than as names.

## Adding a string

1. Add the key to `en.ts`, in the section it belongs to.
2. Add the Spanish counterpart to `es.ts` at the same path.
3. Use `t.<path>` at the call site.

If you skip step 2 the build tells you, with the exact path.
